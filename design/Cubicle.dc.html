Cubicle is an open-source functions platform you run yourself. One binary, your hardware, your data. Python 3.12 and 3.11, sub-40ms cold starts, scale-to-zero, and per-invocation metering you actually own.

Sub-40ms cold starts

Snapshot-restore isolates keep p50 cold starts under 40ms on commodity hardware. Full cold-start telemetry per function — never sampled, never aggregated away.

Encrypted secrets

Envelope-encrypted secrets injected at runtime, never written to disk. Bring your own KMS or Vault — keys never leave your network.

Per-invocation metering

Every invocation metered to the millisecond and attributed to a team. Export to Prometheus for internal chargeback — no external billing pipe.

Free forever. Yours to run.

Apache-2.0 licensed, no open-core bait, no seat limits. Install on one box or a hundred — the whole platform is the same binary.

Requirements

Cubicle ships as one static binary with no runtime dependencies. The control plane and the isolate scheduler live in the same process — you can run a full cluster on a single machine and add nodes later.

{{ r.k }} {{ r.v }}

Install

Pick the path that matches your infrastructure. All three produce an identical cluster — only the supervisor differs.

{{ installFile }}Copy 
{{ installCode }}
Air-gapped installs. Mirror the release tarball and runtime images once, then point registry.mirror at your internal registry. Cubicle never contacts an external endpoint at runtime — there is no license check and no telemetry.

The first request after an idle period is a cold start — typically 30–40 ms once the snapshot is warm on the node. Set min_instances in cubicle.toml to keep isolates resident for latency-critical paths.

Handler signature

Every function exports one entrypoint that receives an event and a context. The same shape is used for HTTP, cron, and queue triggers, so a function can be re-pointed at a different trigger without a code change.

handler.py
def handler(event, context):
    return {
        "statusCode": 200,
        "body": {"ok": True},
    }
index.mjs
export async function handler(event, ctx) {
  return {
    statusCode: 200,
    body: { ok: true },
  };
}

Execution limits

Defaults are 512 MB memory and a 30 second timeout, both raisable per function up to whatever the node pool allows. Filesystem writes go to an ephemeral /tmp that is discarded when the isolate is reclaimed — use an object store or database for anything durable.

Setting a secret

Secrets are envelope-encrypted with a per-function data key, sealed by your KMS root key. They are decrypted into the isolate's memory at cold start and never written to disk or to the log pipeline.

$ cubicle secrets set STRIPE_KEY --function checkout-webhook
? value: ••••••••••••
  sealed STRIPE_KEY · version 3 · kms://vault/cubicle-root

Reading at runtime

python
from cubicle import secrets

KEY = secrets.get("STRIPE_KEY")

Example

Each function carries a cubicle.toml next to its source. Anything set in the console writes back to this file, so the console and GitOps stay in sync.

[function]
name        = "checkout-webhook"
runtime     = "python3.12"
entrypoint  = "handler.handler"

[resources]
memory_mb     = 512
timeout_s     = 30
min_instances = 1
node_pool     = "general"

[trigger.http]
path    = "/hooks/stripe"
methods = ["POST"]

[metering]
namespace = "payments"
